Text‑to‑Speech Accessibility Checklist (6 items)


Provide a visible “Listen to this page” control
Place a clearly labelled button or link at the top of the page so users can easily find and start text‑to‑speech.


Ensure all main text is readable by screen readers
Use real text (HTML), not images of text, so screen readers and TTS tools can access all content.


Use proper HTML structure and landmarks
Use headings (<h1>–<h3>), lists, and <main>, <nav>, <footer> regions so TTS reads content in the right order.


Make controls keyboard accessible
The TTS button must be usable with keyboard only (Tab, Enter, Space) and have a visible focus outline.


Avoid auto‑play audio
Let users start and stop speech themselves. Auto‑playing audio can be confusing or overwhelming.


Use clear, descriptive labels for controls
Button text or aria‑labels should clearly say what they do, e.g. “Listen to page content” or “Stop reading”.
